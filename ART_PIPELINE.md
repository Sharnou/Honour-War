# Honour War — Permanent Sharnou Engine HD 3D Anime-Inspired Art Pipeline

## Locked production identity

HD 3D anime-inspired medieval/fantasy MMORPG/ARPG.

Every visual development cycle is manual/on-demand and begins with authoritative reference analysis. The visual identity remains original Honour War fantasy MMORPG presentation and is never replaced by generic placeholders, strategy presentation, modern/scifi styling or flat prototype art.

## Fixed production sequence

Visual RAG / multimodal reference analysis → visual gap register → regenerated visual brief → Neural4D or Blender authored geometry → Substance 3D Painter material authoring → FBX/OBJ private interchange intake → Sharnou Engine native geometry/material compilation → AVIF raster visual delivery → gameplay/runtime validation → real EXE screenshot → reference comparison.

## Permanent exclusions

- Godot is permanently rejected as the Honour War runtime/build target.
- Unity is permanently rejected as the Honour War runtime/build target.
- Unreal Engine is permanently rejected as the Honour War runtime/build target.
- Meshy is permanently rejected.
- Visual Studio, MSBuild, Windows SDK development installations, CMake and vcpkg are permanently rejected as project development/build dependencies.
- No external programming-tool download or bootstrap is permitted.
- No future visual cycle may restore a retired engine workflow or fallback renderer.
- Development cycles are manual/on-demand; this contract does not reactivate an unattended daily-upgrade system.
- Futuristic/scifi machinery, robots, transformers, factories, rockets and space presentation are excluded from the game identity.

## AVIF-only runtime visual rule

The .avif file format is the only approved shipped raster/visual asset format.

AVIF is used for:
- UI and HUD artwork
- menu and loading artwork
- icons and item/skill/card artwork
- character/monster/pet portrait artwork
- sky/background/distribution artwork
- rendered visual-reference frames and gameplay evidence

The following are permanently rejected from active runtime visual delivery:
- .gltf
- .glb
- .ktx2
- .png
- .jpg
- .jpeg
- .webp
- .gif
- .bmp
- .tga
- .dds

FBX/OBJ are permitted only as private Neural4D/Blender authoring/interchange inputs. They are not shipped runtime visual assets.

Sharnou Engine geometry is an engine-native compiled runtime representation; it is not represented as a GLTF/GLB container. AVIF therefore governs the shipped raster/visual payloads rather than pretending a 2D image container is a 3D mesh container.

## Visual RAG first

Every visual pass starts with reference analysis. The analysis compares the current real gameplay frame, when available, with the locked anchors and records macro/micro gaps in characters, equipment, pets, monsters/MVPs, terrain, architecture, props, lighting, camera, animation, combat VFX and UI.

## Asset authoring

Neural4D is an approved generation source when available. Blender remains the authored-DCC source. Substance 3D Painter is the material authoring stage.

Approved private authoring/interchange:
- FBX: rigged/animated heroes, pets, monsters and NPCs.
- OBJ: approved static environment and prop meshes.

These source formats remain upstream inputs only.

## Sharnou Engine import

Production geometry is processed into Sharnou Engine's native runtime representation and assigned native materials. Each asset receives a stable ID, correct scale/orientation, material slots, collision plan, LOD plan, animation clip list where applicable, and runtime placement/streaming metadata.

## World standard

Every playable map receives authored terrain, architecture, roads, vegetation, props, landmarks and lighting. Empty template maps are not accepted as finished production maps.

## Character standard

All seven base classes and their advanced tiers receive complete full-body models with visible faces, hair, hands, legs, feet, clothing layers, armor, accessories and class-specific weapons. Hero and monster animation must make attacks, hits, movement and skills readable.

## Camera and gameplay standard

The permanent gameplay framing is explicitly Ragnarok Online-inspired while remaining an original Honour War implementation: elevated isometric-style MMORPG camera, left-click navigation/targeting, right-mouse drag camera orbit, wheel zoom, numeric skill inputs and no WASD movement.

The camera must keep the hero readable as a complete character during normal play; feet and legs must not be cropped by default framing.

## Runtime evidence

The final graphical result must be judged from a real Sharnou Engine runtime/Windows EXE frame. Reference images and concept art are inputs, not evidence of gameplay.
